# 代码开发：Codex

**推荐等级：首选** · 最后核验：2026-08-02

[Codex](https://developers.openai.com/codex/) 是当前本站对游戏代码开发的重点推荐。它不是只返回代码片段的聊天机器人，而是能够读取仓库、修改文件、运行命令与测试、检查差异并持续迭代的软件工程代理。

## 为什么适合游戏开发

- 能理解跨脚本、场景、配置和资源导入代码的关联，适合 Godot、Unity、Unreal 及自研工具项目。
- 可以直接处理边界明确的实现任务：角色控制、状态机、编辑器插件、数据导入、存档迁移、构建脚本和自动测试。
- 能实际运行项目命令、读取错误日志、修复问题并重新验证，而不只给出一段未经运行的示例。
- Codex App、CLI、IDE 与云端任务覆盖从本地结对到后台委派；App 支持多个任务线程、隔离工作树、差异审查、Skills 和定时 Automations。
- 可配合图像生成与浏览器能力制作并检查 Web 游戏、工具面板和宣传页面。

## 可以直接交给 Codex 的任务

| 任务 | 推荐委派程度 | 示例 |
| --- | --- | --- |
| 理解项目 | 高 | “找出伤害结算、掉落表和 UI 展示之间的数据流，并标出入口文件” |
| 实现小功能 | 高 | “为现有 Godot 角色加入冲刺，沿用当前状态机并补测试” |
| 修复错误 | 高 | “复现存档升级失败，定位原因，修复并验证旧存档” |
| 工具与批处理 | 高 | “批量检查贴图尺寸和命名，输出报告并提供安全修复模式” |
| 测试与审查 | 高 | “运行测试，审查当前 diff，只报告可复现的正确性问题” |
| 核心玩法决策 | 低 | Codex 可做候选实现与对比，是否好玩仍需实际试玩 |

## 推荐使用方式

1. 在仓库根目录提供精简的 `AGENTS.md`：启动、测试、导出命令，架构边界和不能改动的内容。
2. 用可验收任务描述结果，而不是只说“优化一下”。例如指定目标输入、失败路径和需要运行的测试。
3. 允许它读取足够上下文并操作独立分支/工作树；完成后检查 diff、测试结果和引擎内表现。
4. 把重复工作封装为 Skill 或脚本，例如资源审计、版本发布、截图回归和商店素材检查。

## 当前入口

- [Codex 官方文档](https://developers.openai.com/codex/)
- [Codex App](https://openai.com/index/introducing-the-codex-app/)：集中管理多个代理任务、Skills 与 Automations。
- [Codex CLI](https://developers.openai.com/codex/cli/)：适合本地仓库和终端工作流。
- [Codex Use Cases](https://developers.openai.com/codex/use-cases)：官方案例与可复用任务思路。

::: warning 仍需人工确认
游戏引擎资源和场景经常包含二进制或编辑器隐式状态。即使代码测试通过，也要打开真实项目，检查导入、场景引用、动画、性能和导出结果。发布密钥与平台后台权限不应无条件交给代理。
:::
